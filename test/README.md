# Test scenarios

Run `npm test` to build the package, check the public declaration contracts, and execute all runtime tests. Run `npm run test:coverage` for Node's built-in coverage report and gates: 100% lines, 100% functions, and at least 95% branches. No extra test dependencies are needed.

| Area                      | Scenarios                                                                                                                                                                                                    | Test file                                            |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------- |
| Package                   | ESM default/named exports, declaration entry, no CJS output, real process argv, CommonJS entry rejection                                                                                                     | `erii.test.mjs`                                      |
| Parsing                   | argv snapshot, text/numeric/boolean/repeated values, positional/numeric commands, disabled negation, generated aliases and grouped short flags                                                               | `commands.test.mjs`                                  |
| Registration and dispatch | Primary/short/long aliases, unknown commands, invalid bindings, rebinding, independent instances, execution order, handler exceptions and asynchronous completion                                            | `commands.test.mjs`                                  |
| Lifecycle/context         | Always/default handlers, empty and unknown input, replacement, `start`/`okite`, delegated help/version, current/other command lookup                                                                         | `commands.test.mjs`, `erii.test.mjs`                 |
| Arguments                 | Primary-name precedence, alias redirection enabled/disabled, missing commands/values, positional `_` exclusion                                                                                               | `commands.test.mjs`                                  |
| Options                   | Global/scoped/alias bindings, primary-name exposure, missing/unregistered/empty options, unknown command bindings                                                                                            | `options-validation.test.mjs`, `erii.test.mjs`       |
| Validation                | Built-in/custom rules, valid/invalid/missing input, raw values, string coercion, logging, unknown JavaScript validator names, exceptions, option omission vs command rejection                               | `options-validation.test.mjs`, `erii.test.mjs`       |
| Output                    | Default/partial/reset metadata, empty help, arguments, short/long aliases, command/global options, missing descriptions, optional public command fields                                                      | `output.test.mjs`                                    |
| Conversion                | Camel/kebab case, underscores, empty/uppercase input, object identity/value preservation and key collisions                                                                                                  | `convert.test.mjs`                                   |
| Proxy                     | Alias reads/writes, explicit-key precedence, falsey/null/undefined values, symbols/empty keys, enumeration/JSON, non-writable properties                                                                     | `convert.test.mjs`, `erii.test.mjs`                  |
| Schema                    | Unchanged raw values, validation during dispatch, argument lookup without revalidation                                                                                                                       | `schema.test.mjs`                                    |
| Types                     | Required schema, interface composition, optional arguments, camel-case aliases and collisions, command/option ownership, nullable lookups, value types, handler inference, validator signatures and metadata | `types.ts`, `schema-types.ts`, `validators-types.ts` |

Tests normally import `erii` through its package exports, so they exercise the actual bundle and generated declarations. Conversion utility tests import the TypeScript source using Node's native type stripping to cover helpers not exported by the package. Coverage includes only `dist/index.mjs` and `src/utils/convert.ts`, excluding tests and dependencies.

Each test restores mocked output and temporary argv changes. Consumer smoke tests run in separate Node processes with a timeout. Type tests include `@ts-expect-error` cases, so accepting an invalid public API usage fails type checking.

These tests cover existing behavior, including unknown validator names logging and accepting input when called from JavaScript. Async handler tests verify completion of the handler's work; they do not imply that `start()` returns a promise or awaits handlers.
